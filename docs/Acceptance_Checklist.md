# SparkCanvas AI 上线验收清单

本清单用于判断 SparkCanvas 是否达到可上线产品标准，不再只判断 Demo 是否能启动。

## 1. 产品目标

SparkCanvas 是一个品牌驱动的 AI 画布系统。用户应该能先管理品牌与素材，再用 CAL 语言像写代码一样引用资源，一句话生成可编辑工作流，并把图片、文本、PDF、MP4 等结果沉淀回画布和素材库。

核心闭环：

1. 创建或选择项目，可绑定品牌，也可选择无品牌。
2. 在品牌库中维护 Logo、IP、产品、菜单、门店、模特、文案等素材。
3. 通过 `$logo`、`$dapot.menu.buffet`、`$copy.slogan` 等 CAL 变量引用真实素材。
4. 输入一句 CAL 指令，系统自动创建可编辑工作流节点。
5. 图片生成必须把 `$` 引用中的图片作为真实参考图传给 `@imgen` skill。
6. 生成结果必须显示在画布上，并可预览、重新生成、下载、保存到素材库。
7. 文本、脚本、音频、视频和 PDF 节点必须能继续编辑和重跑。

## 2. 本地启动验收

```bash
npm install
npm run dev
```

打开 `http://localhost:3100`。不要使用 `3000` 端口。

入口验收：

- `/` 和 `/site` 应显示 SparkCanvas 官网首页，不应直接把未登录用户丢进空白工作台。
- 登录、注册或已登录用户点击进入工作台后，应进入 `/workspace`。
- 刷新 `/workspace` 后，前端应继续加载工作台，不能出现 Nginx 404 或空白页。

后端健康检查：

```bash
curl http://localhost:4100/health
```

演示账号仅用于本地和内网验证：

- 账号：`shift`
- 密码：`123456`

生产环境必须禁用公开演示账号，或显式配置受控演示模式。

## 3. 品牌与素材验收

- 品牌管理必须支持创建、切换、编辑、保存。
- 项目创建时必须能选择品牌，也必须支持无品牌项目。
- 切换品牌管理页时，不应无意切换当前画布项目。
- 上传 Logo/IP/产品/菜单等图片后，必须立即显示缩略图。
- 刷新 `/workspace` 后，上传素材仍必须显示。
- 替换品牌槽位图片时应更新原素材，不应制造无法识别的重复素材。
- 每个可引用素材都必须显示可编辑 CAL 标签，例如 `$logo`、`$ip`、`$menu.soup`。
- Assets 页面必须按品牌过滤，并允许修改标签、标题、说明、类型、删除、下载。
- 画布空白处上传图片必须进入素材库，并在画布创建可见参考节点。
- 从图库选择素材必须打开可选图库，不允许是空操作。

## 4. CAL 语言验收

必须支持以下符号：

- `@`：Agent，例如 `@imgen`。
- `$`：品牌资源变量，例如 `$logo`、`$dapot.ip`、`$menu.buffet`、`$copy.slogan`。
- `/`：命令，例如 `/生成海报`、`/write-video-script`。
- `%`：风格标签，例如 `%premium`、`%TikTok`。
- `->`：输出目标，例如 `-> JPG`、`-> PNG`、`-> PDF`、`-> MP4`。

验收要求：

- 首页和工作台输入框都必须支持 `@`、`$`、`/`、`%` 补全。
- 补全列表不能秒退，鼠标滚动和点击必须可用。
- `$` 后为空时不显示无效空项目。
- `$dapot` 应引用 DAPOT 整个品牌上下文和可用素材。
- `$dapot.ip` 只引用 DAPOT IP 图片和相关说明。
- `$copy.slogan` 应展开为品牌 slogan 文本。
- 图片变量不能只出现在提示词文字里，必须作为 `imageReferences` 传给生成 skill。
- 引用缺失时必须给出可理解提示，不允许静默失败。

推荐验收语句：

```text
@imgen /生成海报 使用 $dapot.logo $dapot.ip $dapot.menu.buffet，为 DAPOT 自助火锅生成泰中文 5.1 活动投放海报 %premium -> JPG
```

## 5. 画布工作流验收

- 新建项目默认必须是空画布。
- 一句话生成后，画布应自动出现参考图、提示词、图片生成、输出等节点。
- 节点之间必须支持一对多连接。
- 节点、连线控制点、画布视图必须可拖动并保存位置。
- 线上的 `+` 必须能添加文本、图片、视频、脚本、音频、图库引用。
- 点击图片节点必须打开固定底部编辑器或预览操作，不应被右侧浮层遮挡。
- 图片节点必须能上传、从素材替换、重新生成、下载、保存版本。
- 文本节点必须是可放大的编辑器，可生成故事、文案、表格或脚本。
- 视频节点必须能选择横屏/竖屏、时长、语言、是否配音，并显示任务状态。
- 音频节点必须能保存音频提示词和语言/场景参数。
- 工作流运行按钮必须清晰可见，可按顺序执行当前画布。

## 6. 输出验收

- JPG/PNG 输出必须显示图片预览，按完整图片长边适配显示，不裁半张图。
- PDF 输出必须是真实 `.pdf` 文件，不允许下载 PNG 冒充 PDF。
- MP4 输出必须产出可下载视频 URL，或保持处理中/失败，不允许假成功。
- 多输出任务如果无法全部完成，必须明确标记哪个输出成功、哪个失败。
- 生成产物必须能保存到素材库，并带可编辑标签。

## 7. 模型和 Skill 验收

- 默认图片角色是 `@imgen · image skill`。
- 图片生成走本地 skill 脚本，不应由前端直接请求图片 API。
- 文本、图片、视频模型必须可切换，但默认值必须可用。
- `/api/ai/status` 和 `/api/ai/diagnostics` 只能返回脱敏配置，不得返回密钥。
- 生成失败时必须显示明确原因和下一步动作。

## 8. 国际化验收

- UI 框架必须支持中文、英文、泰文。
- 品牌名、CAL token、用户输入内容不翻译。
- 图片/视频生成参数必须支持内容语言，例如中文、英文、泰文、中泰双语。
- 切换语言后，首页、品牌、素材、画布、节点编辑、教程不应出现大量硬编码中文。

## 9. 自动化验证

```bash
npm test
```

`npm test` 当前实际覆盖：

- TypeScript 类型检查。
- 前后端生产构建。
- 后端本地冒烟测试。
- 登录、工作区加载、品牌创建、品牌资产上传/替换/刷新后持久化。
- CAL 引用解析，图片引用进入 `imageReferences`。
- 一句话生成 JPG/PDF/MP4 工作流。
- PDF 真文件下载。
- MP4 节点状态更新。
- 当前工作流重跑不新建项目。
- 资产和节点保存后可从 `/workspace` 重新加载。

生产路径改动、发布前或排查生产回归时，还必须额外运行：

```bash
npm run test:production-smoke
```

`npm run test:production-smoke` 当前实际聚焦生产路径回归，覆盖：

- 生产环境禁用公开演示账号 `shift/123456`。
- 生产 token 登录与 `/workspace` 鉴权。
- `/generated/*` 生成文件必须鉴权访问。
- 生产环境公开引用状态与 CORS 来源过滤。
- 视频首帧引用在生产路径中使用带签名公开 URL。
- public reference、upload service、object storage 三条生产引用回归脚本。

## 10. 上线阻塞项

以下任一项不满足，不允许公开上线：

- 生产仍开放 `shift/123456` 公共登录。
- 上传/生成文件无需鉴权即可访问。
- MP4 输出假成功但没有视频文件或任务状态。
- 品牌图片上传后无法显示、刷新后丢失或不能引用。
- `$` 图片资源没有真实传给图片生成 skill。
- 新建项目不是空画布，或默认残留旧品牌工作流。
- 工作流运行按钮不可见，用户无法执行当前画布。
- PDF 下载实际是 PNG。
- `npm test` 不通过。
