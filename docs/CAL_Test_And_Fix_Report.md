# SparkCanvas CAL 测试与修复报告

更新时间：2026-05-20

## 本轮目标

- 新建项目 / 新建流程必须从空画布开始。
- CAL 引用能力在首页顶部输入框、底部输入框、节点编辑器中保持一致。
- 兼容旧输入习惯：`@logo`、`@IP`、`#slogan`、`#slogen` 仍可触发引用并转换为 CAL 资源。
- `$logo`、`$product.hero` 等图片资源必须作为真实参考图进入图片生成 skill。

## 已发现问题

1. 空画布被旧迁移逻辑补回默认四节点。
   - 表现：新建画布或重载后出现 Reference / Brand / Prompt / Output。
   - 原因：后端迁移逻辑看到缺少 `brand` 节点时自动合并旧工作流模板。

2. 首页顶部输入框没有接入 CAL 补全。
   - 表现：顶部输入 `@`、`#`、`$` 无列表。
   - 原因：只有底部 composer 和节点编辑器使用了补全组件。

3. `#` 旧文本引用没有纳入新补全触发。
   - 表现：`#slogan` 无法像旧项目一样选择品牌文案。
   - 原因：CAL 新语法改为 `$copy.slogan` 后，前端只识别 `@ / $ %`。

4. `@` 旧图片引用体验断裂。
   - 表现：用户习惯输入 `@logo` 时无法看到图片素材。
   - 原因：CAL 中 `@` 已定义为智能体，未在 UI 层给旧引用提供兼容候选。

## 修复内容

1. 空画布保护
   - 后端新增空画布判断。
   - 如果画布没有提示词，且节点只包含旧自动核心节点，会自动清空为真正空画布。
   - PATCH 更新参数时也不会重新注入默认节点。

2. 全局 CAL 补全统一
   - 首页顶部输入框接入与底部一致的补全组件。
   - 节点编辑器、底部输入框、顶部输入框共用同一套候选数据。

3. 兼容旧写法
   - `#` 触发文本资源候选，例如 `$copy.slogan`、`$copy.brand_name`。
   - `@` 同时显示智能体和兼容图片资源；选择图片资源时插入 `$logo` 等新 CAL token。

4. 测试覆盖
   - smoke test 增加空画布断言。
   - smoke test 增加旧核心节点清理断言。
   - smoke test 保留 CAL 解析、旧 alias、文本/脚本/视频/音频、生成任务、导出验证。

## 已验证结果

- `npm run check` 通过。
- `npm run build` 通过。
- `npm run test:smoke` 通过。
- 浏览器验证：
  - 点击 `New` 后 `.rh-node` 数量为 `0`。
  - 顶部输入 `$lo` 出现 `$logo`。
  - 顶部输入 `#s` 出现 `$copy.slogan`。
  - 顶部输入 `@` 出现智能体和兼容图片资源。

## 后续建议

1. 把 CAL 解析器拆成前后端共享纯函数模块，避免 UI 与后端规则漂移。
2. 增加端到端 UI 测试，覆盖顶部、底部、节点编辑器三个输入入口。
3. 为 CAL 增加语法高亮和解析预览，显示 agents、commands、resources、lockedTexts、tags、params、outputs。
4. 将生成后的图片、视频任务和文本结果统一写入画布资产版本库，支持节点回退和替换。
